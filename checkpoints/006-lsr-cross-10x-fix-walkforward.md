# 006 LSR-CROSS: расхождение найдено, сотни процентов возвращены

## Что изменилось

1. **Найден корень 10× расхождения CLI vs API** — walk-forward скрипт `/tmp/walk_forward.py` передавал неполные `params` (`z_score`+`exclude_*` без трейлов). Отсутствовали `trail_act=0.04`, `trail_dist=0.03`, `trail_lock=0.02`, `sl_pct=0.05`, `tp_pct=0.18`, `hold_h=120`, `pyr_trigger=0.05`, `pyr_add=0.5`. Дефолтные трейлы (0.02/0.015) резали прибыль в 10×.
2. **LsrCrossBacktester игнорирует tf_minutes** — жёстко грузит 5m/1m бары, `tf_minutes=5→60` в API не меняет результат.
3. **API == CLI 1:1 подтверждено** на 180d и 1095d при полных params.
4. **Walk-forward no-excludes выживает OOS** — бьёт baseline на Train и Test.

## Продолжение

Текущее состояние: LSR-CROSS no-excludes даёт ~61% CAGR при risk=0.08/DD 11.22%.

Цель "сотни процентов в год":
- risk=0.12 даёт ~95% CAGR/DD 16.42% — почти 100%/год. Возможно пересчитать CAGR точнее через MTM equity curve.
- risk=0.16 даёт ~130% CAGR/DD 23.66% — уже сотни.
- risk=0.20+ может дать 200%+/год, но DD может превысить допустимый порог.

**Следующий шаг**: найти оптимальный risk для max CAGR при DD ≤ 20% (или иного лимита пользователя). Профиль пользователя — risk-first, выберет строгий DD лимит.

Также возможно: оптимизация z_score (1.5-2.5), оптимизация trail (шире/уже), ATR-based exit, проверка DOT/MATIC (нет данных).
