## Механизмы, которые дали паритет (каждый проверен отдельно)

1. **Объединённый M1-клок.** Канон идёт по `sorted({ts})` всех тикеров и внутри
   timestamp — по списку тикеров (`engine.py:586,601,674`). Мой цикл был «день → тикер»,
   поэтому портфельные гейты (ГО/кластер) срабатывали в другом порядке.
   Теперь: события дня = (ts, ticker) всех M1-баров, `np.lexsort((ticker, ts))`.

2. **Спеки ГО: `COALESCE(go_pgo, go_exch, go)`** (канон `backtest.py:602`), а не `go`.
   MN: 458 vs 591 → 10 vs 8 контрактов, PnL ровно ×1.25.

3. **`eq_cap = 200000` по умолчанию.** Канон 106 НЕ компаундит сайзинг: `base_eq =
   min(equity, eq_cap)` (`executor.py:183`). Без капа equity рос → сайзинг 11 вместо 10 →
   гейт ликвидности 11/21 > 0.5 отбрасывал вход, который канон брал (10/21 = 0.476).

4. **Детектору — только последние 149 дневных баров.** `_trend_bar_cache` канона держит
   ~150 дней (`engine.py:133,314-342`). Я подавал всю историю → EMA60 сеялась иначе:
   5886.6 вместо 5904.4 при seed = SMA(first 60). С окном 149 — совпадение точно.

5. **Вход на первом доступном баре ≥ момента входа (в пределах 5 минут).** У тонких
   тикеров (CM) нет M1-бара ровно в 09:05; канон исполняет pending на следующем
   доступном баре, я требовал точного равенства ts и терял вход.

6. **MTM-DD по M1: worst/best без учёта направления.** `k = step_price*shares/min_step`,
   для шорта `k<0`; best = `max((hi−e)k, (lo−e)k)`, worst = `min(...)`. До фикса для
   шортов best/worst были перепутаны → DD показывался 0.1% вместо 11.9%.

7. **Ликвидность:** `vol` = объём M1-бара входа (`bar_data['vol']` канона), отказ при
   `shares/vol > 0.5`; `vol = 0` НЕ отказ (как в `executor.py:202`).
